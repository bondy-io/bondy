bondy_db: the operation-based re-grounding (Canteen × MST)

The substrate is two layers. Layer 1 (the MST op-log substrate, Auvolat & Taïani) reconciles a grow-only set of operations — legitimately state-based, and correct. Layer 2 (the application CRDT, Canteen / McCrary) produces state by replaying the log through the COG-Interpreter interpret_cog. This re-grounding made interpret_cog the catalogue's sole kernel while preserving every performance lever; it is complete and as-built. The panels below trace the correction: §1 the state-based-fold design that was corrected, §2 a snapshot mid-correction, and §3 the as-built operation-based architecture. The narrative version lives in the CRDT model and the design rationale.

1 · Before — the state-based-fold design (corrected)

Local writes land in the MST op-set (Layer 1, correct). The applier then builds the projection incrementally via apply_event in arrival order using the deprecated state-based folds, and bootstrap uses a merge_states state-join. The real COG-Interpreter (bondy_oplog_crdt) exists but is sidelined — used only at compaction/query, with zero production CRDTs.

2 · The correction, mid-flight (historical snapshot)

Where the code actually sits today, between the drifted baseline (§1) and the target (§3). Layer 1 is untouched. For a table with a crdt_module the applier's per-cell kernel runs the operation-based path (interpret_cog) on both the write seam (step 3) and the read seam (step 3b); the legacy fold kernel still exists and is the default (byte-identical). The projection is eagerly materialised by the applier (Option B), so it is the per-cell interpret_cog checkpoint — hence compaction is pure COG-stability GC with no separate checkpoint re-fold (step 4). That is the one deliberate deviation from §3's compaction box (which draws a redundant interpret_cog(stable COG)→checkpoint step that Option B does not need). Native non-commutative CRDTs, the default flip, and removing merge_states are steps 5–8.

3 · As-built — operation-based (Canteen × MST)

Layer 1 is untouched. The applier's per-cell kernel becomes interpret_cog — the sole semantics — backed by native bondy_oplog_crdt_* modules. Compaction folds each stable COG into a real checkpoint in the projection (Canteen's Domain-Specific DB) and truncates the MST. Reads are O(1) from the materialised projection; read-your-writes folds the live group via interpret_cog. All deprecated state-based machinery is removed.

Projection maintenance: eager-materialised value. The projection holds each cell's materialised value, kept current on write, with interpret_cog as the sole convergence kernel split by commutativity — so reads stay O(1). All three panels depict this design.
Compaction, as-built. Because the projection is materialised eagerly, the projection is the per-cell interpret_cog checkpoint, so catalogue compaction is pure COG-stability GC (replay-before-truncate, then truncate the MST) rather than re-folding a separate checkpoint as §3's compaction box draws. A separate checkpoint would byte-for-byte duplicate the projection; the checkpoint store is explicitly "not a durability layer for the projection." Only the monolithic whole-instance CRDT path still folds a checkpoint.
