# M0 — Fly fault-injection capability spike

The **blocking** first milestone of the Bondy test harness (`_design/test-harness/06 §M0`).
It answers one question before any correctness/perf work relies on Fly: **which
faults from `03 §5` can we actually inject on Fly Machines, and can we confirm
each took effect?** (Firecracker gives root inside the VM, but `CAP_NET_ADMIN` on
the 6PN device and `LD_PRELOAD` are *not* contractually guaranteed — they must be
proven, not assumed.)

## What's here

| File | Role |
|---|---|
| `Dockerfile` | OTP-29 image (`erlang:29.0.5`) of the pinned tag + fault toolbox + probe. Builder tag tracks `deployment/Dockerfile`. |
| `fly.toml` | 3-node cluster manifest: 6PN DNS discovery, per-machine volume, no autostop. |
| `config/bondy.conf.template` | Bootable profile from `03 §2`, key-verified against `schema/bondy.schema`. |
| `setup.sh` | Bring-up hook (Erlang node name from the 6PN IP). |
| `probe.sh` | In-VM capability probe (baked into the image; run as root via `fly ssh`). Emits NDJSON. |
| `run-spike.sh` | Orchestrator: deploy → scale 3 → health-gate → probe each node → render the report. |
| `FLY_FAULT_CAPABILITY.md` | **The deliverable** — the green/red matrix (regenerated by each run). |

## Prerequisites (yours to clear — I can't)

1. **`fly auth login`** — the orchestrator aborts otherwise. (In this session you
   can run it inline: type `! fly auth login`.)
2. A Fly **org** you can create apps in (`FLY_ORG`, default `leapsight`).
3. `jq` on PATH (`brew install jq`).
4. Docker is **not** required for the Fly path (remote build). It *is* required
   for the local-Docker fallback and the M1 walking skeleton.

## Run

```sh
# from the repo root
FLY_ORG=<your-org> just m0-run          # deploy 3 nodes, probe, render report
just m0-logs                            # tail cluster logs
just m0-shell                           # ssh into a node
just m0-down                            # stop machines (idle = volume cost only)
just m0-destroy                         # delete app + volumes (irreversible)
```

`just m0-run` is idempotent. To re-probe a cluster that's already up without
redeploying: `M0_SKIP_DEPLOY=1 ./harness/m0-fly-spike/run-spike.sh`.

## Known unknowns this spike resolves (expect to iterate)

- **`iface`** — the probe assumes `eth0` for `tc`/partition. If the 6PN device is
  named differently, `tc` will "succeed" but affect nothing (the classic
  did-nothing nemesis, `05 R1`) — the ping-RTT confirmation catches this.
- **`fly ssh console` non-interactive `-C`** with a baked script — validated here.
- **Partition confirmation channel** — the probe uses `ss` ESTAB count on :18086
  plus `/metrics` `bondy_cluster_membership_size`; M0 confirms which is reliable.

Nothing downstream trusts a Fly network/clock fault until its row in
`FLY_FAULT_CAPABILITY.md` is ✅.
