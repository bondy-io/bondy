## What each row decides

- **`net_admin_cap`** — is `CAP_NET_ADMIN` granted inside the Firecracker VM? This
  is the precondition for `partition_iptables` and `delay_tc_netem`. If ❌, both
  network faults fall back to local Docker regardless of their own rows.
- **`partition_iptables` / `delay_tc_netem`** — the two Medium/Low-confidence
  faults from 03 §5. These are the reason M0 is blocking.
- **`clock_skew_libfaketime`** — capability only (the probe skews a throwaway
  `date`, not live Bondy). Live skew is restart-time (`LD_PRELOAD` at BEAM start).
- **`disk_fill` / `cpu_stress` / `signal_beam`** — expected High-confidence; rows
  here are a sanity check, not a risk.

## Known open finding to resolve before M4/M5 (not an M0 blocker)

`registry_presence_evict_after` (listed in 03 §2 as a config knob) is **not a
cuttlefish key** at the pinned tag — `schema/bondy.schema` has no presence/evict
mapping. The M0 profile omits it, so EVICT grace stays at its 24h code default.
Any EVICT-dependent property (P5b, presence) must first locate the real override
(code `-define` or `advanced.config`) and correct 03 §2.

## Fallback routing

Any non-✅ row routes its fault class to the local-Docker substrate (03 §6) for
the runs that need it; all other faults and the full k6 scale runs stay on Fly.
